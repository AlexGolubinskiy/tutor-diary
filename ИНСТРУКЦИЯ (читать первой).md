# Дневник для репетиторов — инструкция для проекта Claude

## Что это
Офлайн-дневник преподавателя: расписание недели, группы, тарифы по ученикам, авансы и оплаты.
Одна HTML-страница (PWA) на GitHub Pages, работает на iPad (Safari) и Android (Chrome).
Данные хранятся только в localStorage каждого устройства. Синхронизация — ручная: экспорт и импорт файла.

Репозиторий: github.com/AlexGolubinskiy/tutor-diary, ветка main.
Сайт: https://alexgolubinskiy.github.io/tutor-diary/
Последний коммит: a5c80e7 (версия кэша sw.js: diary-shell-v6).

## Файлы
- index.html — интерфейс и вся логика расписания, оплат и подсказок.
- ledger.js — финансовое ядро в браузере (класс FinancialLedger). Суммы в копейках.
- sw.js — кэш оболочки приложения (cache-first). При любом изменении index.html или ledger.js поднимать имя кэша (diary-shell-vN), иначе старая версия останется у пользователя.
- financial_core_v01.py — эталон финансового ядра на Python. Должен совпадать с ledger.js.
- test_financial_core_v01.py — 39 unit-тестов (python -m unittest).
- Ключи localStorage: tutorDiaryV2 (недели), tutorDiaryLedgerV1 (журнал событий).

## Финансовые правила (утверждены заказчиком)
1. Возвратов нет. Оплаченный урок отрабатывается.
2. Тариф задаётся по каждому ученику с датой действия; действует до следующего тарифа. Тариф меняется раз в полгода или год.
3. Аванс фиксирует цену: деньги, внесённые по тарифу на дату оплаты, покрывают уроки по этой цене. Аванс может быть любой суммы: целые уроки покрываются полностью, остаток («хвост») переносится на следующий урок, доплата — наличными.
4. Урок, оплаченный из аванса, стоит зафиксированную цену, даже если тариф изменился. Когда аванс закончился, уроки стоят по тарифу своей даты.
5. Прямая оплата урока (purpose: lesson) — по тарифу даты урока.
6. Пропуск группы (правило C) не списывается, оплата по нему остаётся.
7. Журнал событий только добавляется. Ошибка исправляется событием REVERSAL, исходное событие не удаляется и не редактируется.
8. Отметка «+» за урок, оплаченный из аванса, списывает аванс автоматически (если нет другой оплаты). Прошедшие дни текущей недели тоже покрываются авансом.
9. На дне, которое покрывает аванс, ячейка оплаты показывает «из аванса». На частичном дне — «аванс: осталось X, доплата Y» как подсказка плана; запись доплаты появляется при отметке «+».

## Что уже сделано
- Расписание на неделю, копирование расписания на следующую неделю (без кнопки очистки).
- Все колонки и строки редактируются прямо в таблице, без окон prompt() (кроме создания группы).
- Новые ученики вставляются по времени; группа держится вместе с участниками, сворачивание и разворачивание.
- Поле «₽/зан.» (тариф) стоит в одной строке с именем ученика (коммит a5c80e7).
- Автосписание аванса на «+», подсказки на будущих и прошедших днях текущей недели.
- Экспорт и импорт резервной копии (версия 3: данные + журнал); импорт отказывает при ошибках финансовых правил.
- Браузерные тесты (Playwright, Python): e2e_auto, e2e_inline, e2e_sort, e2e_plan — все проходят.

## Открыто
- Создание группы всё ещё использует prompt() (количество участников и тариф). Нужно заменить на inline-поля.
- Смена тарифа у ученика, у которого уже есть проведённые уроки, отклоняется журналом. Сценарий не решён.
- Импорт и экспорт журнала не проверены на реальных планшетах.
- В ячейке оплаты частичного дня пока только «из аванса»; доплата видна в подсказке плана, а не в ячейке уже проведённого урока.
- Синхронизации между устройствами нет: у каждого планшета свои данные.
- На некоторых сетях GitHub открывается только через VPN.

## Как работать
- Изменения вносить в рабочую копию, проверять тестами, коммитить и пушить только после подтверждения заказчика («пуш»).
- Перед изменением финансовых правил менять ledger.js и financial_core_v01.py одновременно и проверять совпадение.
- Ответы заказчику — на русском языке.
